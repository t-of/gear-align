# GEAR ALIGN — 歯車の向きを揃えるパズル

**遊ぶ： https://t-of.github.io/gear-align/** （スマホでもそのまま遊べて、アプリとしてインストールもできる）

灰色の**原動力**（ハンドルの付いた無地の歯車）が回すと、噛み合った歯車が隣どうし逆向きに回る。
ただし**歯車を選ぶとそれだけ奥に下がって噛み合いから外れる**
（小さくなって隣との間に隙間ができるので、外れたことが形で分かる）。
「持ち上げて回す」を繰り返して、歯車に付けた**合いマーク**（白い印）を全部同じ向きに揃える。
1 手で持ち上げる数は **1 つ / 2 つ**を選べる。

- 遊ぶ: https://t-of.github.io/gear-align/

## 遊び方

歯車を選んで持ち上げ（1 手で持ち上げる数だけ選ぶ）、操作盤の「原動力を左回り / 右回り」で回す。
合いマークが全部同じ向きになれば揃う。回し方・規則・ルールの変え方・そのほかの機能とシェアは次のとおり。

### 歯車をなぞって回す

ボタンのほかに、**歯車に触れて円を描くようになぞると回せる**（マウスでも指でもよい）。

- なぞった歯車は指についてくる。噛み合っている歯車も、歯数の比のとおり一緒に回る（途中の角度も見せる）
- その歯車の 1 手ぶん（step·360/T 度）回すごとに 1 手として確定する。手数・1 手戻す・記録はボタンと同じ
- 離したとき半分以上回っていればその手まで進めて噛み合わせ、足りなければ元の位置に戻す
- なぞった歯車が画面上で時計回り（v = +1）なら、原動力の向きは d = v·sign(k)。
  原動力のクランクでも、盤面のどの歯車でもよい
- 持ち上げた歯車・原動力から切り離された歯車・持ち上げる数が足りないときは回さず、理由を短く出す
- 動かさずに離したときは、これまでどおり持ち上げ／下ろし（6px 動くまではタップ扱い）。
  角度は指を置いた位置から数えるので、動き出しの判定までに動いたぶんも回る
- 歯車の上では `touch-action: none` にして、なぞる操作をスクロールに取られないようにしている
  （一列の横スクロールは、歯車の無いところを送る）

### 歯数を見れば、回る角度が分かる

噛み合う歯車は「**送られる歯数**」が同じで、回転の向きが逆になる。だから 1 手で
歯を *s* 枚送ると、歯数 *T* の歯車は

> ***s* × 360 / *T* 度**

回る。**歯が少ないほど大きく回る**（歯車比）。画面では

- 歯を **1 枚おきに濃く**してあるので数えやすい
- 歯数ごとに**材質（色）**が違う
- 各歯車の中央に **歯数と 1 手の回転角**（例 `24` / `30°`）… <kbd>L</kbd> で切替
- 盤面の下に **凡例**（歯数 → 回転角 → その歯車が取りうる向きの数）

### 原動力と、持ち上げる数

盤面には必ず**原動力が 2 つ**ある。合いマークを持たない黒染めの歯車で、ハンドルが描いてあり、
持ち上げることはできない（揃える対象でもない）。回して実際に動くのは
**原動力とつながっている歯車だけ**で、切り離された歯車はその手では止まる。

#### 回す向きは「原動力」基準

噛み合う歯車は隣どうし逆に回るので、**どれを基準にするかを決めないと「右回り」が決まらない**。
そこで **2 つの原動力が必ず同じ向きに回るように置いてある**。噛み合うたびに向きが反転するので、
**ぶら下げる相手の市松（sign）を揃えれば**原動力どうしの向きも揃う。

- 格子：n が偶数だと同じ行の左端と右端は市松が逆になるので、右側は 1 行ずらす
- 輪：2 つ目は 1 つ目と添字の偶奇が同じ歯車に付ける
- 一列：両端の市松が揃うのは歯車の数が奇数のときなので、**サイズは奇数だけ**用意している
  （両端以外に付けると、そこを持ち上げたとき端が原動力から切り離されてしまう）
- 星：腕はどれも中心と逆向き＝腕どうしは同じ向きなので、そのままで揃う

`validateLayout()` が「2 つの原動力の回る向きが逆」を毎回検査している。

そのうえで、ボタンは「原動力を左回り（反時計まわり）／右回り（時計まわり）」と言い切り、
**触れているあいだ、2 つの原動力どちらの周りにもその向きの矢印を出す**ので、
言葉を読まなくても分かる（矢印はほかの歯車に隠れないよう一番上の層に描いている）。

#### なぜ 2 つ要るか

原動力が 1 つだと、**それが噛んでいる歯車を持ち上げた瞬間に盤面が全部止まる**。
その歯車だけ実質持ち上げられなくなってしまう。2 つあれば、片方の相手を持ち上げても
もう片方が残りを回すので、**原動力以外はどれでも持ち上げられる**。

| 並べ方 | 原動力の置き場所 | 持ち上げる数 |
|---|---|---|
| 格子 | 左辺と右辺の真ん中 | 1 / 2（2×2 は 1 のみ） |
| 一列 | 両端 | 1 のみ |
| 輪 | 向かい合う 2 辺の真ん中 | 1 / 2 |
| 星 | 2 本の腕の先 | 1 / 2 |

- 星の原動力を**中心に付けない**のは、中心に 2 つとも付けると中心を持ち上げたとき
  両方まとめて外れて盤面が完全に止まってしまうから
- 一列に**2 個持ち上げを出さない**のは、両端が原動力なので隣り合う 2 つ以外を持ち上げると
  必ず真ん中の区間が丸ごと止まり、連動する歯車列としてほとんど成立しなくなるから
- ぶら下げる相手は、**隣の歯車と当たらないものを実際に当たり判定して選んでいる**
  （小さい歯車に大きい原動力を付けると隣に当たる）

#### 切り離してもよい

原動力から切り離す持ち上げ方も自由に選べる。止まる歯車は画面で**薄く点線**になるので、
回す前に分かる。

ただしこれは「揃えられる向き」を増やす。切り離す手があると

> 「A を外したとき動く集合」と「A と B を外したとき動く集合」の差 = **歯車 B だけ**

という手が作れて、歯車を 1 つだけ動かせるようになるからである。実際、1 個持ち上げでは
格子・一列・輪で切り離しが起きないので揃う向きは今までどおり（3×3 なら 1 通り）だが、
**2 個持ち上げでは向きが 4 通り・8 通りと増える**（`m22` の 3×3 では 16 通り、つまりどこにでも揃う）。

この増えぶんを取りこぼさないよう、**「揃えられる向き」は手の張る整数格子で厳密に判定している**
（`src/lattice.js`）。1 手は「動く歯車の集合」の 0/1 ベクトルなので、到達できる x は
それらが張る格子。そこに法 P_j·e_j を足して x ≡ v0 (mod P) が解けるかを見ればよい。
格子は盤面と持ち上げ数だけで決まるので一度組めば使い回せる。

### 追加ルール：揃える向き / 全部ちがう向き

既定では「合いマークが全部同じ向きになればクリア」で、どの向きに揃うかは盤面しだい
（1 通りとは限らない）。設定の「揃える向き」で次のルールに変えられる。

#### 向きの指定（↑ ↗ → ↘ ↓ ↙ ← ↖）

**指定した向きでないとクリアにならない。** 指定した向きに必ず揃えられるよう、
**盤面はその向きから配り直している**（揃った状態から合法手でかき混ぜるので、逆をたどれば
必ずその向きに戻せる）。別の向きで揃えてしまったときは
「向きは揃いましたが、目標は ↑ です」と出る。

**斜めは、その盤面で 45° が作れるステージにだけ出す。** 揃えられる向きは 360/G 度刻み
（G = 歯数の最大公約数）なので、45° を作るには **8 | G** が要る。
そろい歯（16 歯だけ、G = 16）と一列・2 種（16/8 歯、G = 8）が該当し、
大小 16/12 や 20/12（G = 4）では 90° 刻みしか作れないので斜めは出さない。

#### 全部ちがう向き

**すべての歯車をばらばらの向きにする**のが目標。歯車 k が向けられるのは
L/T[k] の倍数の向きだけ（L = 歯数の最小公倍数）なので、これは
**歯車と向きの二部マッチング**になる。増加路法で割り当てが取れたステージにだけ出し、
その割り当てそのものから配り始めるので必ず達成できる。

- 80 ステージ中 **66 で遊べる**。遊べないのは「歯車の数 > 向けられる向きの数」の盤面
  （そろい歯 16 歯の 5×5 は歯車 25 個に対して向きが 16 通りしかない、など）
- 小さい盤面ではかき混ぜても目標のままになることがあるので、シードを少しずらして
  配り直す（同じ URL からは同じ盤面が出る）。それでも駄目ならそのルールは出さない
- ヒントの点線の合いマークは、このルールでは**歯車ごとに違う向き**を指す

### そのほかの機能

- 格子 2×2 〜 6×6（そろい歯・大小 16/12・20/12・24/16・特大 32/24）、
  型抜き格子（ひし形 / 十字 / 斜め帯 / 額縁 / T 字）、一列 5 〜 11 個（2 / 4 / 5 種・大歯車 5 種）、
  輪 8 〜 20 個（4〜5 種・大歯車 6 種）、星 3 / 4 / 6 本（腕 1 段・2 段）と花形 4 / 6 / 9 枚
- 1 手で持ち上げる数 1 / 2
- 揃える向きの指定（自由 / ↑ ↗ → ↘ ↓ ↙ ← ↖ / 全部ちがう向き）
- **ヒント** … 目標の向きをまだ向いていない歯車に、目標の向きの合いマークを点線で重ねる。残り手数も出る
- **次の一手** … 持ち上げる歯車と回す向きを指す
- **自動で解く（ソルバー）** … 押すと**確認をはさむ**（手数を見せて、自己ベストに残らないことを伝える）。
  進めると操作盤の回すボタンの場所が**解答プレーヤー**に替わり、手順を頭から再生する
  - **再生／停止・1 手戻る／進む・最初へ／最後へ・シークバー**で、手順を好きなところから見直せる
    （キーは <kbd>Space</kbd> <kbd>←</kbd><kbd>→</kbd> <kbd>Home</kbd><kbd>End</kbd>、<kbd>Esc</kbd> で閉じる）
  - 1 手ごとに「前の手の歯車を戻す → 次の歯車を下げる → 回す」を別々の動作として見せる。
    戻るときは逆に、下げ直してから逆向きに回す。シークで飛ぶときだけ途中の動きを省く
  - **揃っても完了画面は出さない**。最後に下げていた歯車も戻して、揃った盤面をそのまま見せる
  - 「閉じて自分で続ける」（または「解答を閉じる」）で、いまの盤面のまま手動の操作に戻る。
    解答を見た盤面は、あとで自分で揃えても自己ベストに残さない（`app.assisted`）
  - 再生中は手動の操作（回す・歯車を選ぶ・戻す・ヒント・新しい盤面）を止める
- 1 手戻す、手数と時間、モード × サイズ別の自己ベスト（localStorage）
- **シード** … 同じシードなら同じ盤面。URL（`#モード/サイズ/シード`）で共有できる
- 効果音（WebAudio で生成。音声ファイルは持たない）、キーボード操作

### シェア

- **完了画面の「結果をシェア」** … 「GEAR ALIGN の『格子・大小 16/12 3 × 3』を 12 手・01:23 で揃えました。お手本は 9 手。
  同じ盤面に挑戦してみて！」のような文面に、**同じ盤面が開く URL**（`#並べ方/大きさ/持ち上げ数/向き/シード`）を付ける。
  お手本（配った直後の盤面の解答の長さ）と比べて「お手本と同じ手数！」「お手本より短い！」も入れる。
  解答を見た盤面は、タイムを載せず「解答を見ながら」と書く
- **設定の「この盤面をシェア」** … 遊んでいる盤面を「何手で揃えられる？」とすすめる
- どちらも送る文面を先に見せてから、**共有メニュー**（Web Share が使えるブラウザだけ）・**コピー**・
  **X でポスト**・**LINE で送る**を選ぶ。コピーはクリップボードの API が 1.5 秒で返事をしなければ、
  文面を選んでコピーする方法に切り替える
- リンクを貼ったときのプレビュー（OGP）は `icons/og.png`（1200×630）。`tools/og.html` を
  ./serve.sh のあと Chrome で 1200×630 のスクリーンショットに撮って作った

## アプリとして入れる（PWA）

Chrome・Edge・Safari で開くと、**アプリとしてホーム画面・アプリ一覧・Dock に入れられる**。
入れたあとはブラウザの枠なしで開き、**ネットにつながっていなくても遊べる**。

- 設定（⚙）の**「アプリとしてインストール」**から入れる
  - Chrome / Edge / Android … その場でブラウザのインストール画面を出す（`beforeinstallprompt`。ブラウザの帯は出さない）
  - Safari（iPhone / iPad）… 自分からは出せないので、押すと「共有 → ホーム画面に追加」の手順を出す
  - Safari（Mac）… 「ファイル → Dock に追加」の手順を出す
  - アプリとして開いているときは「インストール済み」になる
- **インストールには https で公開したページが必要**（`localhost` は例外）。スマホの実機で試すときは
  GitHub Pages などに置くこと。`http://192.168.x.x` のような LAN のアドレスでは入れられない
- `manifest.json` … 名前・アイコン・`display: standalone`・テーマ色
- `sw.js` … サービスワーカー。同じサイトのファイルは**ネットを先に見て、つながらなければ保存した版**を返す。
  つながっていれば常に最新が出るので、開発中に古い画面が残らない。字体（Google Fonts）は保存した版を先に返す。
  **ファイルを増やしたら `SHELL` に足す**（足さないと、オフラインで初めて開いたときにそのファイルが出ない）
- iPhone のホーム画面から開くとステータスバーの下まで広がるので、上のバーは `env(safe-area-inset-top)` ぶん下げてある
- アイコンは盤面と同じ歯車の形（`src/gear.js`）から `tools/make-icons.mjs` が SVG を書き出す。
  PNG（192 / 512 / 切り抜き用 512 / iPhone 用 180 / タブ用 32）は、その SVG を Chrome で描いて作った
- Chrome の開発者向けプロトコル（`Page.getInstallabilityErrors`）で「インストールできない理由：なし」、
  サービスワーカーが動いて 19 ファイルを保存していること、**ネットを切って開き直しても盤面が出ること**を確かめた

## データ

端末の localStorage だけ（キーは `gear-align:` で始まる）。外には送らない。

- `gear-align:<コースの id>:<大きさ>` … 自己ベスト `{"moves": 手数, "ms": ミリ秒}`
- `gear-align:sound` … 音の入切（`1` / `0`）
- `gear-align:full` … 完全版か（`1` / `0`）。iOS 版で、ストアの答えが来る前の表示の控え。答えが来たらそちらを信じる
- `gear-align:adClears` … 自分で揃えた回数（通算。全画面広告の回を決める）

iOS 版は、同じキーを端末の UserDefaults（Capacitor の Preferences）にも控える。iOS 版の無料版だけ、広告（Google AdMob）が端末の情報を Google に送る（https://t-of.github.io/privacy/ ）。

### 検証

```
node test/logic.test.mjs     # 規則と幾何
node test/solve.test.mjs     # 手順の正しさと最短性
node test/entitlement.test.mjs  # 無料と完全版の分け方、全画面広告の回
./serve.sh                   # そのうえで http://localhost:8000/test/ui.html
```

- `logic.test.mjs`
  - **幾何と原動力**：`validateLayout()` が 全モード × 全サイズで、噛み合う組の中心間距離が
    半径の和か、歯先が相手の「歯の帯」（歯底円〜歯先円）に入っているか、噛み合わない組が
    ぶつかっていないか、**曲がり角がピッチの整数倍か**、**奇数の輪が無いか**を全部見る。
    加えて、**原動力が 2 つあって別々の歯車に噛んでいること**、原動力が 1 つの歯車だけに
    噛んでいること、原動力以外はどれでも持ち上げられること、
    **どれを持ち上げても盤面が全部止まることはないこと**を確認
  - **総当たり**：各並べ方の最小構成（格子 2×2 / 一列 4〜6 個 / 輪 4 個 / 星 4 個、
    最大 98304 状態）について、揃った状態から合法手（**切り離す手も含む**）で行ける範囲を
    **全部列挙**し、そのうち約 120 状態で `solvableDirections()` の予測と突き合わせる
    （型抜き格子と 2 段の腕の星も、同じ規則の最小構成で確かめている）
    （予測の計算は手順を組み立てるので、全状態で回すと重いため抜き取り）。
    1 個持ち上げ・2 個持ち上げの両方で確認
  - 原動力が持ち上げられないこと、持ち上げた歯車が回らず、**原動力とつながっている歯車だけが**
    歯数どおりに回り**切り離された歯車は止まったまま**であること、undo を
    全モード × 全サイズ × 持ち上げ数 × 20 局面で確認
  - **向き指定ルール**：指定した向きには必ず揃えられること、別の向きで揃えてもクリアに
    ならないことを全並べ方 × 持ち上げ数 × 4 方向で確認。
    **斜め**は指定できる並べ方すべて × 4 方向、
    **全部ちがう向き**は遊べる 66 ステージで「目標が達成状態になっている」
    「1 つでも重なればクリアでない」「配った直後は達成していない」を確認
- `solve.test.mjs`
  - 全モード × 全サイズ × 持ち上げ数 × 各 120 局面で手順が必ず作れて必ず揃うこと、
    狙った向きに揃うこと、手順が使う持ち上げ方が正しい形であること

## 見た目

機械式時計のムーブメントを下敷きにしている。光は常に**左上から**で、陰影・影・ボタンの面取りをこの向きで揃えてある。

- **地板** … ペルラージュ（円を重ねた仕上げ）の金属板に、四隅のビスと刻印（いまの並べ方と大きさ）
- **材質で歯数を塗り分ける** … 8 歯 = 銅、12 歯 = 真鍮、16 歯 = 鋼、20 歯 = 緑アルマイト、
  24 歯 = 焼き青、原動力 = 黒染め鋼（`toneOf()` / `DRIVER_METAL`）。凡例にも材質名を出す
- **歯車の形** … 歯面は膨らんだ曲線で細らせた歯形（ピッチ円上の歯厚 < 谷幅なので相手と重ならない）。
  16 歯以上はリム・スポーク・ボスを残して肉抜きし、穴から地板が見える
- **光が回らない** … 歯と円板は中心対称の塗り、方向のある陰影・ボス・ルビーは `.counter` の層に描き、
  歯車と同じ時間・同じ緩急で**逆回転**させる。二つが打ち消し合うので、歯車が回ってもハイライトは動かない
- **影** … 全部の歯車より下の層にまとめて描く（隣の歯車に影が乗らない）。持ち上げると影も小さく薄くなる
- **合いマーク（向きの印）** … 実物の歯車を組むときに合わせる印にならって、ボスからリムへ白い塗料の線を引き、
  リムに幅の広い塗りとポンチの打刻を置く。光の層より下に描くので、塗料も金属と同じ陰影を受ける。
  真上が歯になるか谷になるかは歯車ごとに違う（市松の片方は谷）ので、**歯そのものは塗らない**。
  線は真上のスポークの上に通る。ラベルを消すと中央に軸受けのルビーが見える
- **操作盤** … 黒い小窓の計器（手数・時間・ベスト・揃えられる向き）、真鍮ベゼルの回転キー、アイコン付きの補助キー
- 字体は Chakra Petch / JetBrains Mono（Google Fonts、読み込めなければシステムの字体）。
  テストが `cssRules` を読むので、フォントの `<link>` には `crossorigin` を付けてある

|---|---|---|---|
| **格子** | 正方形に並べ、上下左右が全部噛み合う | **2 種類まで** | 残りは 1 つながり |
| **型抜き格子** | 格子から ひし形 / 十字 / 斜め帯 / 額縁 / T 字 を切り抜く | 2 種類まで | 形しだい（額縁は 1 つながり、T 字は木） |

| **星** | 中心 1 つと放射状の腕（1 段 / 2 段 / 36 歯の花形） | いくらでも | 腕ごとに分かれる（木） |

### 歯車の種類（8〜36 歯・8 種類）

| 歯数 | 材質 | 1 手 2 歯送りの角度 | 使っている並べ方 |
|---|---|---|---|
| 8 | 銅 | 90° | 一列・輪・星 |
| 12 | 真鍮 | 60° | 格子・一列・輪・星 |
| 16 | 鋼 | 45° | 格子・一列・輪・星 |
| 20 | 緑アルマイト | 36° | 格子・一列・輪・星 |
| 24 | 焼き青 | 30° | 格子・一列・輪・星 |
| 32 | 紫アルマイト | 22.5° | 格子（特大 32/24）・一列・輪 |
| 36 | ローズゴールド | 20° | 一列・輪・星（花形の中心） |
| 12（原動力） | 黒染め鋼 | — | 全部 |

歯数を足すときの制約は 3 つある。

1. **全部の歯数の最大公約数 G が 4 の倍数**であること。揃えられる向きは 360/G 度刻みで、
   盤面は上下左右のどれかに揃った状態から配るので、G = 2 だと左右から配った盤面が解けない。
   10 歯・18 歯を入れた案はこれで落とした（`logic.test.mjs` が全モードで検査している）
2. **格子では斜め隣の大歯車どうしがぶつからない**こと。間隔 d = R大 + R小 に対して
   2·(R大 + m) < √2·d が要る。24/16・32/24 は満たすが、24/8・16/8 は満たさない
3. **輪と星は角と腕の向きがピッチの整数倍**であること（輪は 4 の倍数、星は腕の本数が中心の歯数を割り切る）。
   花形の中心 36 歯には 4・6・9 枚の花びらを付けている（12 枚だと 12 歯の花びらどうしがぶつかる）。
   輪・大歯車は歯数の並びで角の歯車が当たるので、8 / 12 / 16 個のどれでも当たらない並び
   （36・12・32・24・16・8）を総当たりで選んだ

型抜き格子は格子の部分グラフなので、噛み合いの条件（間隔が一様・曲がり角が 90°・
奇数の輪が無い）は自動的に満たされる。ただし原動力の置き場所は形ごとに変わるので、
**歯車が無い格子点のうち「隣り合う歯車がちょうど 1 つ」の場所**を全部数え上げ、
市松が揃う組からいちばん離れた 2 つを選んでいる
（隣が 2 つ以上ある場所に置くと、宣言していない噛み合いができてしまう）。

### 噛み合うための条件

形を考えるうえで効いてくるのは次の 3 つ。

1. 噛み合う 2 つの**中心間距離が R₁ + R₂**（= m(T₁+T₂)/2）
2. ある歯車から出る**噛み合い方向どうしが、その歯車のピッチ 360/T の整数倍だけ離れている**こと。
   歯は 360/T ごとにしか無いので、相手の方向に歯（または谷）を向けられる角度は飛び飛びになる。
   **曲がり角はピッチの整数倍にしかできない**。90° の角は T が 4 の倍数なら作れる
3. **閉じた輪は偶数個**。噛み合うたびに回転の向きが反転するので、奇数だと一周して食い違う

そして輪については、辺の長さを 1 つおきに足し引きすると

> e₁ − e₂ + e₃ − … = (R₁+R₂) − (R₂+R₃) + (R₃+R₄) − … = 0

が**恒等的に**成り立つ。つまり閉じた輪があっても、半径の側に追加の条件は出ない。
**閉じるかどうかは位置だけの問題**になる。

### 軸に平行な格子だけが 2 種類に潰れる

正方格子では上の「閉じる条件」が、単位正方形ごとに dx_j = dy_i という形で効いてしまう。
間隔が一様に決まり、さらに

> R(i,j) + R(i,j+1) = d （どの行でも）　R(i,j) + R(i+1,j) = d （どの列でも）

を解くと R(i,j) = ( d + (−1)^(i+j)·D₀ ) / 2、つまり**市松に並んだ 2 種類の半径**にしかならない。
半径 R = m·T/2 は歯数に比例するので、歯数も 2 種類まで。**これは格子に特有の事情で、輪一般の話ではない。**

### 輪：前半と後半を同じにすると閉じる

長方形の輪を、上辺・右辺・下辺・左辺の順に歯車をたどるものとする。歯数を**点対称**、
つまり前半と後半で同じ列にすると、e_{k+m/2} = e_k になり、

> 上辺の長さの合計 = 下辺の長さの合計　　右辺 = 左辺

が自動的に成り立って、輪はぴたりと閉じる。角は 90° なので歯数は 4 の倍数から選ぶ。
これで**歯数を何種類でも混ぜたまま輪が作れる**。用意してあるのは 8〜20 個の輪で、4〜6 種類（36 歯・32 歯の大歯車を含む輪もある）。

輪は格子と同じく **2 連結**（どの歯車を 1 つ外しても残りが 1 つながり）なので、
1 つの入力で残り全部が回る、という機械としての筋も通っている。
一列と星は木なので、内側の歯車を持ち上げると本当は伝達が切れる
（このアプリは「残りは連動したまま」という規則で動かしている）。

### 星：腕の本数は中心の歯数を割り切ること

中心から k 本の腕を出すと、腕の方向は 360/k おき。条件 2 より、これが中心のピッチ
360/T_c の整数倍でなければならないので、**k は T_c を割り切る数**に限られる。
中心を 24 歯にしてあるので腕は 3・4・6 本（8 本も条件は満たすが、腕どうしがぶつかる）。
5 本は 72° / 15° = 4.8 で条件を満たさず、検証器が弾く。

### 採らなかった形

**稲妻（ジグザグ）** も試した。曲がり角 90° は全歯数で条件を満たすが、
1 つ飛ばしの歯車どうしが必ずぶつかる。45° にすると（歯数は 8 の倍数に限られ）衝突は消えるものの、
帯の高さが 46〜57 しかなく一列とほとんど見分けがつかないので採用していない。

**4 枚歯**も一時入れていた（一列・輪・星では噛み合いも可解性も成立した）。
ただしピッチ円半径 15 に対して歯が 7.5 も出るので実体はほぼ「4 つの羽」で、
歯車に見えないうえ小さすぎたのでやめた。いまの下限は **8 枚歯**（ピッチ円半径 30）。
なお、向きの印はいまは矢印ではなく合いマーク（「見た目」を参照）で、リムの上に置いているので
歯数が少ない歯車でも歯に埋もれない。

## パズルの仕組み

### 盤面と手

歯車 k の回転量を「歯 何枚ぶん送られたか」a[k]（整数）で持つ。角度は a[k]·360/T[k] 度。
噛み合いの向きを s(k) = ±1 として、1 手は

> a[k] ← a[k] + d·step·s(k)  （持ち上げた歯車を除く）

**z[k] = s(k)·a[k]** と置き換えると、1 手はただの

> **持ち上げた 1 個を除く全部に +d·step**

になる。以降はこの z で考えると見通しがよい。歯数がバラバラでも同じ形のまま扱える
（違うのは各座標の法 T[k] だけ）。

### 揃えられる向きは盤面ごとに決まっている

歯車 k を d=+1 方向に持ち上げて回した正味回数を n[k]、手の総数（符号つき）を C とすると、
1 手で L 個持ち上げるので Σn[k] = L·C、z[k] の総変化量は step·(C − n[k])。
原動力は合いマークが無いので条件なし（n = 0）、持ち上げられない歯車も n = 0 なので
C ≡ v0[k] (mod P[k]) が要る。

向き c（角度 c·360/G、G = gcd(全部の歯数)）に揃えるには step·v[k] ≡ e[k] (mod T[k]) が要る。
g[k] = gcd(step, T[k]) が e[k] を割らなければその向きには行けない。割れるときの解は
v[k] ≡ v0[k] (mod P[k])、P[k] = T[k]/g[k]。あとは P[k] を足し引きして Σv[k] を N−1 の倍数に
できるかどうかで、届く範囲は h = gcd(N−1, P₁…P_N) の倍数。したがって

> **Σv0[k] ≡ 0 (mod h)** … これを満たす向き c にだけ揃えられる

盤面は「揃った状態から合法手だけでかき混ぜて」作るので、必ず解ける。
出発点の向きは上下左右からランダムに選ぶ（全部 0 から始めると答えが常に ↑ になってしまう）。

### 最短手順

条件は結局この 2 つだけ：

> n[k] ≡ C − v0[k] (mod P[k])　かつ　Σn[k] = L·C　（L = 1 手で持ち上げる数）

手数は Σ|n[k]| なので、これを最小にすればよい。S を直接走査せず **S mod L**
（Λ = P[k] の最小公倍数）で場合分けすると、各 n[k] の候補は
(rho − v0[k]) mod P[k] に P[k] の整数倍を足したものに定まる。あとは
**Σn[k] mod (L·Λ) を状態にした最短経路**として、0 に近い候補から数本ずつ試して最小費用を選ぶだけ。
盤面の探索は要らない。

L = 2 のときは、求めた n[k] を「1 手で 2 個」に組み直す必要がある。組めるのは
**その 2 つを外しても電源が全員に届くペア**だけなので、多い歯車から順に許されたペアを探し、
端数や偏りで組めないときは同じ歯車に +1 と −1 を足して（差し引き 0 のまま）組み直す。
それでも駄目なら手数の少ない順に次の候補を試す。このぶん L = 2 の手順は最短とは限らない。

ここまでは「どこも切り離さない手」だけを使った組み立てで、短い手順が出る。
切り離す手を使って別の側に移ってしまった局面では、**切り離す手を 1 手だけ頭に置いてから
もう一度これを解く**。それでも駄目なら最後の手段として格子から直に組み立てる
（必ず解けるが長くなる）。

最小である傍証として、`test/solve.test.mjs` は「お手本を 1 手進めるたびに残り手数が
きっかり 1 減る」ことを確かめている（最短手順の後ろ半分はやはり最短なので、1 ずつしか減らないはず）。
